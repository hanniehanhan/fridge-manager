# 치와와의 냉장고

韓文介面的冰箱食材管理課堂作業。以奶油白和飽和黃呈現，使用 HTML、CSS、原生 JavaScript，不需要套件安裝、登入或後端。

**已接入使用者提供的逐格表情動畫，網站由既有 GitHub Pages 設定發布；程式更新後仍須確認正式網站結果。** 找不到圖片時顯示韓文提示，食材功能仍可使用。原始碼儲存庫：[hanniehanhan/fridge-manager](https://github.com/hanniehanhan/fridge-manager)。正式網站：[치와와의 냉장고](https://hanniehanhan.github.io/fridge-manager/)。

## 本機使用

在專案資料夾的終端機執行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

開啟 http://127.0.0.1:8000 ，保持終端機執行；按 Ctrl+C 停止。若原伺服器已在執行，直接重新整理即可。不要直接雙擊 HTML；網址或連接埠改變會使用不同來源的瀏覽器資料。

## 功能

- 新增、修改名稱、數量（至少 0.001，可用小數）、單位、到期日、儲存位置。
- 依到期日排序，支援名稱搜尋、冷藏／冷凍／常溫與到期狀態組合篩選。
- 區分已過期、今天到期、未來 1～3 天、4 天以上；使用裝置當地日曆日期，跨午夜及返回頁面會更新。
- 「다 먹었어요!」先成功保存已用完狀態，再播放約 3.3 秒的兩輪咬嚼、舔嘴與滿足表情演出，餐盤食物同步減少；可在紀錄中查看並復原最近一次吃完。
- 復原保留完整原始食材資料，但復原快照不跨重新整理保留。已用完紀錄本身會保留。
- 刪除必須確認，與吃完分開；不播放吃完動畫。
- 儲存失敗不顯示成功、不改資料；讀取或解析失敗暫停修改以保護原資料。
- 輸入以 textContent 顯示；沒有預設食材。
- 使用者「애니메이션 줄이기」與系統 prefers-reduced-motion 任一生效即減少動畫；沒有音效。
- 日期提示不代表食用安全判定，已過期食材另行提醒，不建議食用。餐盤演出是操作完成的幻想畫面，不是餵狗建議。

## 角色與表情影格

- `assets/chihuahua-sprites.png`：使用者提供的 4×4 原始素材表，1254×1254，RGBA，保留原檔。
- `assets/frames/00.png`～`15.png`：切割與對齊後的 16 張透明 PNG，各 320×320。角色高度約 286px，水平置中，腳底基準 y=304。獨立檔案不會露出鄰格。
- `assets/frames/alignment.json`：來源切割邊界、各格範圍與輸出位置。
- `scripts/prepare_sprites.py`：使用 Python 標準庫的可重跑切割工具，不須安裝套件。以透明間隙分格、等比例最近鄰縮放，不重畫角色；原圖角色本身的細微輪廓差異仍需用播放畫面確認。
- `assets/chihuahua.png`：原有 1254×1254 靜態參考圖，保留作為備援。

預載 16 格全部成功後才切換逐格動畫；載入中或失敗使用原靜態圖，失敗會顯示韓文提示，不阻擋管理功能。全部素材使用相對路徑及 image-rendering:pixelated。

待機約每 5 秒眨眼；滑鼠停留吃完按鈕或鍵盤焦點在按鈕時，首頁及按鈕旁預覽播放約 1.15 秒流口水，間隔約 1.15 秒再重播；離開且失焦即回待機。手機直接點擊即可操作，不依賴 hover。吃完保存成功後，原卡片與首頁顯示張嘴、咬下、左右咀嚼兩輪，再吐舌、舔右／左嘴角、滿足閉眼、張眼。食物在兩次咬下時由完整變半份，再變空盤。

使用者或系統減少動畫啟用時，停在張眼影格，不眨眼、不流口水，吃完直接更新並顯示提示。重新整理期間資料狀態以保存紀錄為準，不需要等動畫完成。

## 資料保存限制

- 食材維持原 `yellow-fridge-v1`，設定使用 `chihuahua-motion-v1`，不搬移、不重設舊資料。
- 資料僅存於同一瀏覽器、同一網站來源的 localStorage，不在 Git、伺服器或雲端。
- 重新整理及一般重開瀏覽器可保留；清除網站資料、無痕工作階段結束或瀏覽器清理儲存可能失去資料。
- 手機、電腦及不同瀏覽器不會同步。本機網址與正式網址資料分開，部署不會自動搬移。
- 此版沒有備份匯入／匯出功能。修改前的 `.local-backups/` 是程式快照，不是食材備份。
- 若讀取錯誤持續，先從開發者工具備份儲存鍵的原始內容再處理；不要未備份就清除網站資料。

## 檢查與驗收

若有 Node.js：

```sh
node --test test.cjs
node --check animation.js
node --check app.js
node --check storage.js
node --check date-utils.js
```

自動測試使用模擬 DOM、計時器與記憶體儲存，不寫入真實瀏覽器。它不能驗證真實圖片、排版、原生視窗及輔助技術。

請親自確認（待驗證）：

1. 等素材載入後，確認首頁約每 5 秒眨眼，耳朵完整且腳底不跳動。手機／桌面角色不可遮按鈕。
2. 首次空清單引導；舊資料仍在；新增、修改、重新整理與重開頁面保存正常。
3. 昨天、今天、3 天後、4 天後的排序與標示；搜尋／組合篩選／無結果提示。
4. 滑鼠進入吃完按鈕／鍵盤 Tab 聚焦時看流口水；點擊後看張嘴、咬下、左右咀嚼兩輪，接著舔嘴、滿足。兩次咬下時確認餐盤由兩份→一份→空盤。快速連按只處理一次。
5. 動畫中重新整理仍在已用完紀錄；動畫中／結束後復原，原資料正確；刪除取消／確認正常。
6. 儲存權限被拒時吃完不播放動畫，復原失敗仍能重試；讀取／JSON 解析失敗有錯誤且不覆蓋。
7. 減少動畫設定重新整理仍保留；系統偏好同樣生效。鍵盤與螢幕閱讀器成功提示、跨分頁保護、跨午夜更新正常。
8. 未來真正部署前，在儲存庫子路徑下確認圖片與 CSS／JS 均能載入。

### 新版動畫額外驗收（待驗證）

- 在吃完動畫中按復原、重新整理、切換紀錄／篩選，應保留正確資料並清理演出。
- 勾選減少動畫或啟用系統偏好，確認立即停用表情演出；取消勾選後系統偏好仍具有優先效果。
- 在開發者工具 Network 封鎖 `assets/frames/*` 後停用快取並重新整理：應回到原靜態圖、顯示韓文提示；新增、吃完、紀錄、復原均可用。取消封鎖後重新整理應恢復。
- 實際檢查角色切換有無抖動、素材原有輪廓差異、手機顯示尺寸、鍵盤與螢幕閱讀器通知。

## 碗與 hover 修復驗收

- 冰箱為背景圖層；角色與像素碗放在同一 pet-stage，碗在最前方。碗約角色寬度 1/3，固定在前腳前方偏下，不跟表情切換移位；空盤仍保留碗。
- 吃完按鈕旁新增不遮擋操作的表情預覽，避免滑到下方按鈕時看不到首頁角色。預留預覽位置，顯示／隱藏不改按鈕位置。
- 頁首出現減少動畫說明時，文字會列出是 app 設定、裝置／瀏覽器設定，或兩者同時生效；不要把依偏好停用當成載入失敗。
- 自動測試涵蓋新增後 hover、修改後 hover、focus、mouseleave／blur、停留重播、hover 後吃完優先、預載完成重新起播與重渲染按鈕重接。
- 320、390、430 與 1440px 的場景邊界目前是 CSS 數值模型檢查，並非真實瀏覽器截圖驗證。尚需在這些寬度檢查：空清單／有食材／流口水／吃東西時碗都完整、不遮臉胸、不溢出。
- 本機及正式網站仍需實際用滑鼠與鍵盤確認整段影格播放、左右咀嚼、離開恢復與按鈕旁預覽；手機直接點擊吃完。若正式站仍是舊版，待 Pages 發布後重新整理或停用快取確認。
